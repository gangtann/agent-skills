# 抖音纪录片级短视频

把一个话题做成：一份有出处的资料笔记、一篇 3000–5000 字有观点的文章、一份数据核实记录、一张逐镜分镜表、一条 **1920×1080 横屏**成片，以及 4:3 横封面和 3:4 竖封面各一张。画面用网页（canvas + three.js）逐帧渲染，所以每一帧都可控、可复现。纪录片质感靠**实拍素材**打底：从白名单素材站下载免费商用的空镜，调色后铺在镜头底层，程序画面负责数据图表、图解和片名。

开始前先读 `references/brief.md`：那是用户写给「报复性熬夜」的原始任务书，也就是这个 skill 的质量标准。完整范例在 `examples/revenge_sleep/`（竖屏版：资料笔记、文章、分镜、script.json、shots.js、audio.py、cover.html）。**横屏实拍版**在 `examples/revenge_sleep_h/`（实拍素材的 vid 写法、左文右图构图、数据核实记录、横竖两张封面），新片子优先参考它。

## 用户的长期偏好

- **画幅：横屏 16:9（1920×1080）。** 用户 2026-10-14 明确要求「做的视频是横屏的而不是竖屏的」。工程默认就是横屏（`format.json` 为 `landscape`）；只有用户点名要竖屏时才改成 `portrait`。brief 里写的「竖屏 9:16」已被这条取代。
- 不要"AI 味"：画面要像纪录片，不要卡通、图标堆砌、空背景加一行字；文案要像人写的，避免模板化排比和空洞金句。
- 旁白用**云希**（zh-CN-YunxiNeural，`tts.py`），用户明确觉得比剪映「解说小帅」好。语速约 **300 字/分**（`tts.py` 默认 -4%，实测 298）；用户 2026-10-14 嫌 285 字/分（-8%）稍慢。只有用户点名要剪映音色时才走 `jianying.py`。
- **数据必须核实**：每个数字、引语、年份都要回到一手来源核对，见 `references/fact-check.md`。用户原话：「这种数据一定要核实」。
- **画面上不放出处小字，也不要片尾资料来源卡**（用户 2026-10-14 要求删掉）。出处写进 `04_数据核实记录.md`，发布时在简介里加一行「数据来源」。引语后面可以署说话人（「— 一位规培医生」），但不写媒体名。口径（期别、人群、对照组）仍然要讲清楚，写进旁白或正文。
- **实拍素材优先用中国城市和中国人**（用户 2026-10-14 要求「换成中国城市和中国人的素材」）。
- 发布：不加 AI 声明；只有用户明确说"发布"才发；优先用抖音桌面客户端。标题 ≤30 字。用户说「最好发成草稿」时，填好后点「暂存离开」，不要点「发布」。
- 交付目录：`~/Desktop/抖音配音素材/NN_中文名/`，每条视频一个带编号的文件夹（接着已有最大编号往下排），里面放 `<名>_成片.mp4`、`<名>_封面.png`、`<名>_竖封面.png`、`01_资料笔记.md`、`02_文章.md`、`03_分镜脚本.md`、`04_数据核实记录.md`、`素材授权.md`，中间文件放 `素材/`。
- **实拍素材白名单**（用户 2026-10-14 确认，名单内直接下载不用逐条问，事后给台账）：Pexels、Pixabay、Coverr；Mixkit 只限 Free License；Freesound 只限 CC0。名单外的来源、AI 生成画面都要先问。一律走 `footage.py`，它会拒绝名单外的域名并记授权台账。
- 阶段确认：默认每个阶段交付后等用户确认（资料 → 文章 → 分镜 → 成片）。用户说"不要停/不要问我，直到做出视频"时就一路做完，只在真正被卡住时才找用户。

## 流程

### 阶段一：资料笔记 → `01_资料笔记.md`

按 brief 的六个维度收集（概念溯源、数据、中文真实案例、社会结构、思想资源、科学/医学），重点在中文语境，数量要"足够"（报复性熬夜那期约 110 条）。

- 每条带编号（如 O-1、D-3、C-5）、一句话内容、**来源链接**、年份，并标注「可上画面」或「可作旁白」。
- 查不到原始出处或数字对不上的，放进单独的「未核实，不使用」清单，不进文章和视频。企业报告标「企业报告」，观察性研究标「相关性」，示意图标「示意」。
- 结尾写一段**核心观点**草案，交给用户确认方向。

### 阶段二：深度文章 → `02_文章.md`

3000–5000 字，一个明确的判断贯穿全文。推进顺序：现象 → 个体为何如此 → 结构为何如此 → 我们真正交出去的是什么 → 出路（具体，不鸡汤）。用真实案例和细节开场，不说教、不制造焦虑；金句要长在论证里，全文提炼出**一句记得住的话**，它会成为视频的收尾金句和 QA 项。范例：`examples/revenge_sleep/02_文章.md`。

### 阶段三：视频

**1. 旁白脚本 `script.json`**：从文章里压缩出约 900 字、55–60 句的口语旁白，按镜头分组。结构：钩子（前 3 秒一个戳心的问题 + 强画面）→ 片名卡 `TITLE` → 5 章左右（每章前一个 `CH<n>` 章节卡）→ 首尾呼应 → 金句 → 互动问题（结尾停在这里，默认不加片尾资料页）。数字写成念出来的样子（"四亿四千万"），画面上再用阿拉伯数字。

**1.5 数据核实 → `04_数据核实记录.md`**：旁白定稿后、配音之前，把每个数字、引语、年份都回到一手来源核对一遍（可以派一个后台 agent 去做，主线程同时搭画面），并同步修改旁白、画面、文章和资料笔记。方法和踩过的坑见 `references/fact-check.md`。

**2. 搭工程**（工程目录放在会话 scratch 或用户指定处，不放桌面）：

```bash
bash ~/.claude/skills/douyin-doc-video/scripts/new_project.sh <工程目录>
cd <工程目录> && export PATH="$PWD/bin:$PATH"
.venv/bin/python tts.py && python3 build_timeline.py durs.json   # 先配音，再定时间线
```

**3. 分镜 → `03_分镜脚本.md`**：在 `shots.py` 里逐镜写场景、景别运镜、画面（实拍素材写明作者）、画面文字/数据、声音、转场，`python3 gen_storyboard.py 片名` 生成表格（时间和时长自动来自真实配音）。镜头要有变化：推拉摇移、景别切换、视差、景深，意象串联全片。视觉规范见 `references/visual-system.md`。

**4. 实拍素材**：按分镜给需要「真实感」的镜头找空镜（城市夜景、街道、地铁、写字楼、卧室、手部特写……），细节见 `references/footage.md`。用内置浏览器在素材站搜索，取文件直链：

```bash
python3 footage.py add <直链> --page <素材页> --author 作者 --id 名字   # 只收白名单，自动记台账
python3 footage.py prep 名字 [--ss 起点 --t 时长]                       # 转成画幅一致、可逐帧跳转的片段
```

在镜头里用 `vid: { src: '名字', in, kb, pan, grade }` 打底，`draw` 再叠压暗、图表和文字。章节卡也用实拍打底：`chapter(n, '标题', warm, { src })`。配音定稿后跑 `python3 check_clips.py`，确认每个镜头的素材都够长（不够就调慢 speed、换 in，或者用数组在中途硬切）。

**5. 画面 `web/shots.js`**：照分镜实现每个镜头，可以大量借用范例里的场景（卧室侧脸、3D 城市、数据图表、走廊、地铁、通知、章节卡）。每改一轮就出联系表检查：

```bash
node rec.js shots stills/all && bash sheet.sh stills/all 35 s1.png S01 S02 TITLE S04 S05 S06
```

`rec.js shots` 会自动检查画面文字：出安全区、字号低于下限（横屏 28px）都会列出来，要清零。再逐张看：主体是否明确、有没有遮挡和重叠、文字是否都在安全区（横屏 x 140–1700，y 90–760）、单屏是否 ≤2 行/20 字、亮背景上的文字有没有压暗带。横屏构图用左右三分：主体放一侧，文字放另一侧（侧向压暗用 `scrimX`），不要照搬竖屏的「上字下图」。

**6. 声音**：在 `sound_plan.py` 里给序章和每章选情绪（dark → pulse → drone → warm，跟随 压抑 → 共鸣 → 思考 → 余韵），按镜头铺环境音（room/city/hum/subway）和点状音效，然后 `.venv/bin/python audio.py`。

**7. 出片**（渲染约 14 帧/秒，4 分钟要 9 分钟左右，放后台跑）：

```bash
node rec.js video final_silent.mp4 && .venv/bin/python mix.py
node rec.js cover 封面.png            # 横封面 1440×1080（4:3），底图 web/cover_bg.jpg 取片中一帧实拍
node rec.js cover34 封面_竖.png       # 竖封面 1080×1440（3:4）：抖音自动裁的会切掉标题，要单独做
bash finalize.sh <中文名> ~/Desktop/抖音配音素材/<NN_中文名>
```

`finalize.sh` 会把响度标准化到 -14 LUFS，并额外生成 `<名>_预览720p.mp4`，用 SendUserFile 发这个给用户看，1080p 成片太大不适合直接发。

引擎细节、命令和 shots.js 的 API 见 `references/engine.md`。

## 交付前 QA（逐项检查，并把结果告诉用户）

1. **全片自动扫描**：`.venv/bin/python qa_frames.py <成片> --shots`。它报「空画面」（连续 1.5 秒以上只有一行字或一个小元素，覆盖率 < 0.15）和「整体偏暗」（亮度中位数 < 26）。空画面必须清零。偏暗就提高曝光、多用实拍。基准：竖屏「报复性熬夜」15 处空画面、亮度 21；横屏实拍版 0 处、亮度 40。新片子不能比横屏实拍版差。
2. **随机 5 帧**：`.venv/bin/python qa_safe.py <成片> 5` 生成带红色遮挡区的对比图，打开看。每帧都要有主体、光影和信息；落在转场黑场或空画面上的，回去给那个镜头补画面文字或缩短空镜。
3. **UI 遮挡**：任何文字、数据、字幕都不能进红区，不拥挤。
4. **一句记得住的话**：说出是哪一句，在第几秒出现。
5. **数据都核实过**：`04_数据核实记录.md` 覆盖了片中每个数字和引语，旁白、画面、文章三处一致；没有用到「未核实」清单里的东西；画面上没有出处小字。用了实拍素材的，交付目录里要有 `素材授权.md`（finalize.sh 自动生成，只列片中用到的素材）。可辨认的人脸不能出现在负面文案下面。
6. **比上一期改进了什么**：具体列出（画面、排版、安全区、声音、语速……）。

## 发布到抖音

只有用户明确说"发布"（或"存草稿"）时才执行。用抖音桌面客户端，按 `references/publishing.md` 操作：

- 上传成片，填写标题（≤30 字）、一句简介和 4–6 个话题（逐个从下拉建议里点选）
- 上传 4:3 横封面，再在「竖封面3:4」→ 编辑封面 → 上传 `<名>_竖封面.png`（不要用自动生成的竖封面）。先用 窗口 → 填充 放大窗口
- 简介：一句钩子 + 一行「数据来源：……」 + 话题
- 不加自主声明（AI 声明），设为公开、立即发布
- 用户要草稿就点「暂存离开」；要发布就点「发布」，然后刷新「内容管理」，确认新作品状态为「审核中」，再把结果告诉用户

## 卡住时

- 剪映点不动（computer use 报 "could not verify which document"）时，不要绕过这个检查，直接用 `tts.py` 云希。
- 屏幕锁定时 computer use 截图失败（`ioreg -n Root -d1 -a | grep -A1 CGSSessionScreenIsLocked`），其余步骤照常做，只把需要屏幕的步骤留到解锁后。
- edge-tts 偶尔网络失败，`tts.py` 自带重试；仍失败就稍后重跑（有缓存）。
